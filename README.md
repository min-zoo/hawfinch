# 호핀치 추석 디저트 선물세트 예약 시스템

카페 호핀치에서 추석 선물세트 사전 예약을 받는 웹페이지입니다.

- 손님이 **매장 픽업**과 **택배 발송** 중에 먼저 고르고, 고른 방법에 맞는
  내용만 입력합니다.
- **직원용 페이지**에서 픽업·택배를 한 목록으로 보고 처리 상태를 넘깁니다.
- 픽업은 **매장에서 결제**, 택배는 **계좌이체 확인 후 발송**합니다.

## 설치 순서 (한 번만 하면 됩니다)

프로그램 지식 없이 따라 할 수 있게 적었습니다. 순서대로만 해주세요.
전체 20분 정도 걸립니다.

### 1단계 · 예약을 모아둘 구글 시트 만들기

1. [sheets.new](https://sheets.new) 에 접속해 새 스프레드시트를 만듭니다.
2. 왼쪽 위 제목을 **"추석 선물세트 예약"** 으로 바꿉니다.
3. 위쪽 메뉴에서 **확장 프로그램 → Apps Script** 를 누릅니다.
4. 새 탭에 코드 편집기가 열립니다. 안에 있던 내용을 **전부 지웁니다.**
5. 이 저장소의 `apps-script/Code.gs` 파일 내용을 **전부 복사해서 붙여넣습니다.**
6. 붙여넣은 코드 위쪽에 이런 줄이 있습니다:

   ```js
   var ADMIN_KEY = '바꿔주세요1234';
   ```

   따옴표 안을 **직원들만 아는 비밀번호**로 바꾸세요. (예: `hawfinch2026!`)
   이 비밀번호는 나중에 직원용 화면에 로그인할 때 씁니다.

7. 위쪽 **저장(💾)** 버튼을 누릅니다.

### 2단계 · 예약을 받을 주소 만들기

1. 같은 화면 오른쪽 위 **배포 → 새 배포** 를 누릅니다.
2. 왼쪽 톱니바퀴(⚙️) → **웹 앱** 을 선택합니다.
3. 아래처럼 설정합니다:
   - **설명**: 아무거나 (예: 추석예약)
   - **다음 사용자로 실행**: `나`
   - **액세스 권한이 있는 사용자**: **`모든 사용자`** ← 꼭 이걸로!
4. **배포** 를 누릅니다.
5. 권한을 묻는 창이 뜨면 **액세스 승인** → 본인 구글 계정 선택 →
   "이 앱은 확인되지 않았습니다" 화면이 나오면
   **고급 → (프로젝트 이름)(으)로 이동** → **허용** 을 누릅니다.
   (본인이 만든 코드라서 안전합니다.)
6. 마지막에 나오는 **웹 앱 URL** 을 복사합니다.
   `https://script.google.com/macros/s/....../exec` 처럼 생겼습니다.

### 3단계 · 복사한 주소를 페이지에 넣기

`assets/config.js` 파일을 열어 **맨 아래** 줄을 찾습니다.

```js
sheetUrl: '',
```

따옴표 안에 2단계에서 복사한 주소를 붙여넣습니다.

```js
sheetUrl: 'https://script.google.com/macros/s/....../exec',
```

> 이 파일에서 **매장 이름, 전화번호, 선물세트 이름과 가격, 픽업 날짜**도
> 함께 바꿔주세요. 파일 안에 어디를 고치면 되는지 한글로 적혀 있습니다.

### 4단계 · 웹사이트 켜기 (무료)

1. 깃허브에서 이 저장소 페이지로 갑니다.
2. 위쪽 **Settings** → 왼쪽 목록에서 **Pages** 를 누릅니다.
3. **Source** 를 `Deploy from a branch` 로,
   **Branch** 를 `main` / `/ (root)` 로 고른 뒤 **Save** 를 누릅니다.
4. 1~2분 기다리면 주소가 나옵니다:

   | 용도 | 주소 |
   | --- | --- |
   | 손님용 (카톡에 올릴 링크) | `https://min-zoo.github.io/hawfinch/` |
   | 직원용 (직원들만) | `https://min-zoo.github.io/hawfinch/admin.html` |

**끝입니다.** 손님용 주소를 카톡 채널이나 인스타 프로필에 올리면 됩니다.

## 평소 사용법

**손님**

1. 링크를 열면 **매장 픽업 / 택배 발송** 중 고릅니다.
2. 선물세트 수량을 고릅니다.
3. 픽업이면 수령 날짜·시간, 택배면 받는 분·주소·발송 희망일을 적습니다.
4. 신청하면 `HFC-0100` 같은 예약번호가 나옵니다.
   이 화면에 **입금 계좌와 금액**이 함께 안내됩니다. 픽업도 택배도
   미리 입금해 주셔야 준비에 들어갑니다.
5. **예약 내용 이미지로 저장** 을 누르면 예약번호가 적힌 그림이 앨범에
   저장됩니다. 아이폰은 그림이 뜨면 길게 눌러 “사진에 추가” 를 고르시면
   됩니다.

**직원**

`admin.html` 주소로 들어가 비밀번호를 입력하면 목록이 보입니다.

- 위쪽에 예약 건수 / 픽업·택배 비율 / 처리 대기 / 세트 수량 / 예상 매출이
  자동 계산됩니다.
- 이름·연락처·주소·예약번호로 **검색**, 픽업·택배·날짜·상태로 **걸러보기**가 됩니다.
- 오른쪽 **상태**를 목록에서 고릅니다.

  | 상태 | 뜻 |
  | --- | --- |
  | 대기 | 아직 결제·입금이 확인되지 않음 |
  | 입금확인 | 계좌로 입금이 들어옴 |
  | 현장결제 | 매장에서 직접 결제 (지금은 쓰지 않습니다) |
  | 완료 | 픽업 전달 완료 또는 택배 발송 완료 |

  **새 예약은 픽업·택배 모두 `대기` 로 시작합니다.** 둘 다 미리 입금을
  받기 때문입니다. `assets/config.js` 의 `defaultStatus` 에서 바꿀 수 있고,
  이 값은 Apps Script 를 다시 배포하지 않아도 바로 반영됩니다.

  매장에서 받기로 되돌리고 싶으시면 `pickup.prepay` 를 `false` 로 바꾸고
  `defaultStatus.pickup` 을 `'현장결제'` 로 두시면 됩니다.

  이 목록은 `assets/config.js` 의 `statuses` 에서 바꿀 수 있습니다.
  바꾸실 때는 `apps-script/Code.gs` 의 `ALLOWED_STATUS` 도 같은 값으로
  맞추고 Apps Script 를 다시 배포해야 합니다.

- **현금영수증** 칸에는 손님이 신청한 내용이 보이고, 그 아래 **미발행 /
  발행 완료** 버튼으로 매장이 실제로 발행했는지 표시합니다. 신청과 발행은
  별개이니, 발행하신 뒤 눌러 두시면 빠뜨리지 않습니다.
- **취소** 버튼을 누르면 **취소 사유를 적는 칸**이 뜹니다. 적고 확인을
  누르면 취소 처리되고, 취소한 날짜·시각과 사유가 함께 기록됩니다.
  (줄 아래에 작게 표시되고, 구글 시트와 엑셀 파일에도 들어갑니다.)
  줄이 회색으로 바뀌고 집계(건수·수량·매출)에서 빠지지만 **기록은
  남습니다.** 잘못 눌렀으면 **되돌리기** 로 대기 상태로 돌아갑니다.
  (되돌리면 취소 날짜와 사유는 지워집니다.)
  구글 시트에서 줄을 직접 지우지 마시고 이 버튼을 쓰세요.
- **준비 목록 보기** 를 누르면 날짜별로 무엇을 몇 개 만들어야 하는지 나옵니다.
  픽업은 수령일, 택배는 발송 일정으로 묶이고 취소된 건은 빠집니다.
  작업 지시서로 그대로 쓰시면 됩니다.
- **엑셀로 저장** 을 누르면 지금 보이는 목록이 엑셀 파일로 내려받아집니다.
  배송지 주소도 함께 들어 있어 그대로 송장 작업에 쓰실 수 있습니다.
- 구글 시트를 직접 열어서 봐도 똑같은 내용이 들어 있습니다.
- **휴대폰에서도 볼 수 있습니다.** 화면이 좁으면 표가 카드 형태로 바뀝니다.

## 자주 바꾸게 되는 것들

전부 `assets/config.js` 파일 하나에서 바꿉니다.

| 하고 싶은 일 | 바꿀 곳 |
| --- | --- |
| 매장 이름·전화·주소 | `shop` |
| 예약번호 앞글자 | `codePrefix` (지금 `HFC` → HFC-0100) |
| 예약번호 시작 번호 | `codeStart` (지금 100 → HFC-0100 부터) |
| 예약 시작일 변경 | `openDate` (이 날짜 전에는 신청이 잠깁니다) |
| 예약 마감일 변경 | `closeDate` |
| 세트 가격·이름 수정 | `products` 안의 `name`, `price`, `desc` |
| 세트 추가 | `products` 안의 `{ ... }` 한 덩어리를 복사해 붙여넣고 내용 수정 |
| 품절 처리 | 해당 세트의 `soldOut: false` → `soldOut: true` |
| **수량 한도** | 해당 세트의 `stock` 에 숫자 (예: `50` → 50개까지만 받고 자동 품절) |
| 개인정보 동의 문구 | `privacy.items` |
| 픽업 날짜·시간 | `pickup.dates`, `pickup.times` |
| 요청사항 칸 다시 넣기 | `showMemo` 를 `true` 로 (지금은 꺼져 있습니다) |
| 택배 발송 일정 문구 | `delivery.shipPeriod` |
| 픽업을 아예 안 받기 | `pickup.enabled: false` |
| 배송비 금액 | `delivery.fee` (지금 3500) |
| 무료배송 기준 | `delivery.freeOver` (지금 60000) |
| 입금 계좌 | `bank` 의 `bankName`, `account`, `holder` (픽업·택배 공용) |
| 픽업도 미리 입금받기 | `pickup.prepay` (지금 `true`) |
| 택배 입금 확인 후 발송 | `delivery.prepay` (지금 `true`) |
| 현금영수증 받기/끄기 | `delivery.cashReceipt.enabled` |
| 픽업에는 현금영수증 안 받기 | `delivery.cashReceipt.forPickup` 을 `false` 로 |
| 택배를 아예 안 받기 | `delivery.enabled: false` |

> 픽업과 택배 중 하나만 `enabled: true` 로 두면, 고르는 첫 화면을
> 건너뛰고 바로 그 예약서가 열립니다.

바꾼 뒤 저장하고 깃허브에 올리면 1~2분 안에 웹사이트에 반영됩니다.

> **바꿨는데 화면이 그대로라면** 브라우저가 옛날 파일을 기억하고 있는
> 것입니다. `Ctrl + Shift + R`(맥은 `⌘ + Shift + R`)로 강제 새로고침해
> 보세요. 손님 브라우저에서도 같은 일이 생기지 않도록, 파일을 고친 뒤에는
> `sh stamp.sh` 를 한 번 실행하고 커밋하면 됩니다.

## 수량 한도 (재고)

`assets/config.js` 의 세트마다 `stock` 에 숫자를 넣으면 그 수량까지만
받습니다. 넣지 않으면(`null`) 제한이 없습니다.

- 손님 화면에 **10개 이하로 남으면** "N개 남았습니다"가 뜹니다
- 다 팔리면 **자동으로 품절**로 바뀌어 담을 수 없습니다
- 두 손님이 동시에 마지막 하나를 담아도 **저장소에서 한 명만 통과**시킵니다
- **취소된 예약은 수량에서 빠집니다** (다시 팔 수 있게 됩니다)

## 새 예약 알림 받기

`apps-script/Code.gs` 위쪽의 `NOTIFY_EMAIL` 에 이메일 주소를 넣고 다시
배포하면, 예약이 들어올 때마다 메일이 옵니다. 비워두면 보내지 않습니다.

```js
var NOTIFY_EMAIL = 'hawfinch@example.com';
```

메일이 실패해도 예약 접수는 정상으로 진행됩니다.

## 가짜 예약 막기

손님용 페이지 주소는 누구나 볼 수 있으므로, 장난이나 자동 프로그램이
예약을 밀어 넣지 못하도록 네 겹으로 막아 두었습니다.

| 장치 | 하는 일 |
| --- | --- |
| 숨은 칸 | 사람 눈에 안 보이는 칸. 자동 프로그램만 채우므로 값이 오면 거부 |
| 최소 작성 시간 | 페이지를 연 뒤 3초 안에 제출되면 거부 |
| 중복 접수 | 같은 번호로 2분 안에 같은 내용이 또 오면 거부 |
| 몰아 넣기 | 같은 번호로 10분 안에 5건을 넘기면 거부 |

실제 손님이 걸리지 않도록 여유 있게 잡았습니다. 한 분이 여러 건을
나눠 신청하는 것은 막지 않습니다. 숫자를 바꾸시려면
`apps-script/Code.gs` 위쪽의 `GUARD` 를 고치고 다시 배포하세요.

> 막지는 못합니다. 다만 손님 개인정보는 구글 시트에 있고 직원 비밀번호는
> 공개되지 않으므로, 최악의 경우에도 **가짜 예약이 몇 건 들어오는 정도**이며
> 직원 화면에서 취소 처리하시면 됩니다.

## 알아두실 점

- **`sheetUrl` 을 비워두면 "연습 모드"** 로 동작합니다.
  예약이 매장으로 전송되지 않고 그 기기에만 저장되어, 설치 전에 화면을 미리
  둘러볼 때 쓸 수 있습니다. 화면 위에 노란 안내가 뜹니다.
- **직원용 화면의 비밀번호는 도난 방지용 잠금장치 수준**입니다.
  가족·직원끼리 쓰기에는 충분하지만, 아주 민감한 정보를 담지는 마세요.
  손님 연락처가 들어 있으니 비밀번호는 외부에 공유하지 마세요.
- **택배 주소는 민감한 정보입니다.** 손님 이름·연락처와 함께 배송지가
  구글 시트에 쌓이므로, 직원용 비밀번호를 외부에 공유하지 마세요.
- 손님 개인정보(이름·연락처·주소)는 사장님의 구글 시트에만 저장됩니다.
  추석이 끝나면 시트를 정리해 주세요.
- 예약번호는 `HFC-0100` 부터 순서대로 자동으로 매겨집니다.

## 문제가 생기면

| 증상 | 확인할 것 |
| --- | --- |
| 예약 신청이 "전송 실패"로 뜸 | 2단계에서 **액세스 권한**을 `모든 사용자`로 했는지 |
| 직원 화면에서 "비밀번호가 올바르지 않습니다" | `Code.gs` 의 `ADMIN_KEY` 와 입력한 값이 같은지 |
| 코드를 고쳤는데 반영이 안 됨 | Apps Script 에서 **배포 → 배포 관리 → 연필(✏️) → 버전: 새 버전 → 배포** |
| 시트의 열이 코드와 안 맞음 | 새 코드를 배포하면 다음 예약이 들어올 때 자동으로 맞춰집니다 |
| 웹사이트 주소가 404 | Pages 설정 후 1~2분 기다렸는지, Branch 가 `main` 인지 |

## 디자인

흰 여백을 넉넉히 쓰고, 연둣빛을 기본으로 하늘색을 포인트로 얹은
차분한 느낌입니다. 글씨는 **Pretendard**, 선택 버튼과 상태 표시는
동글동글한 알약 모양입니다.

색을 바꾸고 싶으면 `assets/style.css` 맨 위 `:root` 부분의 값만
고치면 전체가 한 번에 바뀝니다.

| 이름 | 색 | 쓰이는 곳 |
| --- | --- | --- |
| `--green` | `#b9d46f` | 선택된 버튼, 신청 버튼, 준비완료 표시 |
| `--green-soft` | `#edf3dc` | 안내 상자 배경 |
| `--green-text` | `#5f7c2a` | 가격, 강조 글씨 |
| `--blue` / `--blue-soft` | `#a5d8f3` / `#e6f4fc` | 예약번호, 준비대기 표시 |
| `--ink` / `--ink-soft` | `#5c5c5c` / `#737373` | 본문 · 보조 글씨 |

글씨 색은 흰 바탕에서 읽기 힘들지 않도록 명도 대비를 맞춰 두었으니,
색을 바꾸실 때는 너무 연한 회색은 피해 주세요.

Pretendard 글꼴은 jsDelivr CDN에서 불러옵니다. 혹시 불러오지 못하면
윈도우는 맑은 고딕, 맥은 애플 SD 산돌고딕네오로 자동 대체됩니다.
